# AI Studio — локальный MVP

Требуется Python 3.12+. Внешних Python/Node зависимостей нет.

```sh
cd /workspace/Syntetic-studio-2
python server.py
```

Откройте в браузере адрес локального сервера на порту 8000. По умолчанию доступ разрешён только с этого компьютера. Для облачной среды: `AI_STUDIO_HOST=0.0.0.0 python server.py`. Не публикуйте сервер в открытом интернете: MVP предназначен для одного доверенного пользователя, авторизация не реализована.

Данные сохраняются в `data/studio.sqlite3`. Другую директорию задаёт `AI_STUDIO_DATA`, порт — `PORT`. Процессы нужно запускать заново после восстановления среды.

## Рабочий процесс

1. Создайте проект и заполните концепцию.
2. Напишите сценарий или импортируйте UTF-8 TXT/MD; добавьте сцены.
3. Импортируйте файлы в медиатеку с подтверждением классификации.
4. Добавьте персонажей, локации, реквизит и их референсы.
5. Создайте планы и назначьте отдельные START/END изображения из медиатеки.
6. Задайте правила и исключения в каноне, вручную проведите материалы через статусы утверждения.
7. Выполните структурную проверку.
8. Скачайте резервную копию. Восстановление создаёт отдельный проект и проверяет SHA-256 медиа.

История сценария и канона сохраняется при изменениях. Изменение эталона помечает планы для повторной проверки. Физическое удаление материалов не предусмотрено, поэтому связанные и утверждённые файлы не теряются. Одновременная запись устаревшей версии проекта отклоняется.

python -m unittest discover -s tests -v

## Границы первой версии

Реализованы ручные операции производства и структурный контроль. Генерация, визуальный AI-анализ, монтаж и MP4-экспорт относятся к следующим версиям. Сценарии импортируются только как TXT/MD, разбиение предлагается по заголовкам сцен с ручным подтверждением. Восстановление отдельной редакции возможно вручную из истории; архив восстанавливает проект целиком. Медиа хранятся в SQLite в JSON/base64: ограничение 20 МБ на файл и 100 МБ на запрос/проект. Для крупных производств потребуется отдельное файловое хранилище и потоковый импорт. Работа проверяется на Python/Linux; другие ОС отдельно не тестировались.

## План производства
После сохранения или импорта сценария открывается отдельный раздел с полным порядком работ и текущими состояниями. Заголовки «Сцена 1», «Эпизод 1», INT./EXT., ИНТ./НАТ. распознаются локально без нейросети. Если заголовков нет, предлагается одна сцена. Подтверждение создаёт сцены и по одному черновому плану; повторное подтверждение не дублирует их. Изменённые сцены предлагаются заново без удаления старых материалов. Статусы рассчитываются из данных проекта. Генерация, монтаж и экспорт честно отмечены недоступными.

Обновление Windows: остановите приложение, сохраните резервную копию проекта и замените файлы кода из нового ZIP GitHub в прежней папке. Сохраните папку data без изменений. Запустите START_WINDOWS.bat и обновите страницу Ctrl+F5.

## Новый процесс: три вкладки

1. **Мои проекты** — создание и открытие.
2. **Материалы проекта** — общий текст (вставка или TXT/MD), картинки PNG/JPEG/WebP/GIF с пояснениями. Сохраните материалы перед анализом. В «Подключение нейросети» задайте `https://anymodel.org/v1`, точные имена текстовой/визуальной и графической моделей из сервиса и API-ключ.
3. **Производство** — вертикальная последовательность из 10 этапов с известными материалами, результатами, историями вариантов и согласованием. Ручные редакторы доступны внутри этой вкладки.

AI разбирает материалы в структурированный JSON, отделяет существующий сценарий от замысла, выделяет библию, персонажей, правила и референсы. Только после согласования добавляются записи в проект. После «Утвердить и продолжить» автоматически запускается следующий доступный этап, который снова останавливается на согласовании. Это может инициировать платный запрос. Можно задать правки и запросить новый вариант текстового этапа.

API-адаптер предполагает OpenAI-совместимые `POST /chat/completions` (JSON response_format и image_url для анализа) и `POST /images/generations` (PNG/JPEG в b64_json). Конкретные модели AnyModel должны поддерживать эти параметры; реальный сервис в облачной среде не проверен из-за сетевой блокировки, ключа также нет. Названия моделей не выдумываются — их нужно указать из личного кабинета провайдера.

Изображения создаются по одному: очередной недостающий START/END кадр отправляется на согласование, после утверждения назначается плану. Генератор получает текст библии и правил; передача визуальных референсов в генератор пока не реализована. Текстовый API анализирует сами загруженные изображения.

Настройки с ключом хранятся в `data/ai-settings.json`, не выдаются через API чтения и не входят в архив проекта. Не отправляйте папку data другим людям. Приложение рассчитано на одного доверенного пользователя; запросы длительные, работают пока открыт сервер, фонового возобновления после остановки нет.

MiniMax H3 на локальном ПК: подключение отложено по решению пользователя. Видео, автоматический визуальный контроль, звук, монтаж и экспорт отмечены неподключёнными и автоматически не выполняются. Полностью автономный выпуск фильма пока недоступен.

### Проверка подключения и список моделей

В «Материалы проекта → Подключение нейросети» введите базовый URL и API-ключ, затем нажмите «Проверить подключение и получить модели». Сервер обращается к `GET <базовый URL>/models` с ключом, показывает состояние и заполняет два списка моделей. Выберите модель для текста/анализа и модель изображений, затем сохраните подключение. Проверка списка сама по себе не сохраняет новые настройки.

Не требуется вводить названия моделей вручную. Если провайдер не публикует назначение моделей, приложение не угадывает его по имени: оба списка содержат возвращённые API идентификаторы. Успешная проверка подтверждает доступ к каталогу, но не баланс, поддержку изображений или выполнение генерации. При ошибке показывается причина, устаревший список очищается. При изменении URL требуется заново ввести ключ; сохранённый ключ другому провайдеру не пересылается. Перенаправления при проверке каталога запрещены.

### Особенности AnyModel из документации провайдера

Адрес `https://anymodel.org/v1`, авторизация Bearer и `GET /models` подтверждены документацией. Для AnyModel `403` с JSON-кодом `insufficient_quota` означает неактивный аккаунт (например, неподтверждённую почту или блокировку), а `402 / payment_required` — недостаток средств. Приложение различает их по коду ответа, не делает вывод о состоянии аккаунта из одного HTTP 403 и показывает безопасный request_id для поддержки, если он предоставлен.

Каталог AnyModel разделяется по полю kind: без kind — текст, imageToText — анализ изображений через чат, image — генерация картинок. Полные ID с префиксами сохраняются без изменений. Для других API без метаданных назначения остаётся общий список. Реальный статус аккаунта пользователя не проверялся: тесты используют ответы по документированной схеме.

### HTTPS на Windows

На Windows запросы каталога, текста и изображений выполняются через системный curl.exe: это использует тот же клиент, которым проверено соединение пользователя с AnyModel. TLS-проверка включена; ключ передаётся через stdin-конфигурацию, не через аргументы процесса или файлы. Тело POST временно сохраняется в закрытом временном каталоге и удаляется после запроса. Перенаправления и автоматические повторы не выполняются, чтобы не пересылать ключ другому адресу и не дублировать платные задания. На остальных ОС остаётся Python urllib. Успешный запрос без ключа с HTTP 401 подтверждает доступность соединения, но не валидность ключа или возможность генерации.

## Карточки персонажей, локации и номера сцен

В редакторе «Сценарий» каждая сцена имеет порядковый код S001, S002… Назначьте ей локацию и отметьте участвующих персонажей. При новом AI-разборе раскадровки эти связи предлагаются моделью; существующие сцены требуют ручной привязки. Недостающие карточки локаций из новой раскадровки добавляются как черновики.

Перед генерацией кадров система проверяет карточки участвующих персонажей и локаций. Если нет визуального эталона, сначала генерируется эталон и предлагается на утверждение. Уже загруженные референсы и их карточки должны быть утверждены в «Каноне». Затем запрос кадра включает описания карточек и изображения в параметре images; END дополнительно получает START. Модель обязана поддерживать изображения-референсы: при отказе провайдера запрос без них автоматически не повторяется. Это повышает согласованность, но не гарантирует идентичность — результат нужно проверить вручную.

Созданные медиа сохраняют scene_ids, reference_ids и использованный промпт. В медиатеке отображаются номера и файлы скачиваются как S001_M003.png; общий референс нескольких сцен — S001_S002_M001.png. Несвязанные материалы обозначаются GLOBAL, сцену можно назначить в медиатеке. Исходные названия и содержимое файлов сохраняются. Нумерация сцен отражает порядок списка; связи строятся по неизменным ID. Старые проекты получают номера при чтении и сохраняют их при следующем сохранении. Для перегенерации прежнего кадра снимите назначение START/END в раскадровке; исходный материал останется в медиатеке.

## Компактные изображения и партии

Изображения отображаются миниатюрами шириной до 220 px. Нажатие открывает просмотр; кнопка «Размер 100%» показывает оригинал с прокруткой, «Вписать в окно» возвращает масштаб по размеру окна. Закрытие — кнопкой или Escape.

На этапе изображений выберите размер партии от 1 до 10. Это число разных готовых производственных задач, а не вариантов одного промпта. Одновременно идут не более трёх запросов. Если независимых задач меньше, партия будет меньше: END ждёт утверждённого START, кадры ждут референсов. Настройка сохраняется вместе с проектом при выполнении операции. Успешные результаты частично неудачной партии сохраняются и показываются вместе с ошибками; автоматических повторов нет. «Утвердить и продолжить» утверждает все показанные успешные результаты и запускает следующую партию выбранного размера. Каждый запрос может оплачиваться отдельно. Сервер должен оставаться запущенным до окончания партии.

## Ответы на вопросы разбора

Под пунктами «Чего не хватает» и «Вопросы к вам» доступны отдельные поля ответов и прикрепление файлов (до 20 МБ каждый). Можно ответить текстом, указать «создать с помощью AI», «не требуется» или «решим позже». Кнопка «Сохранить ответы» сохраняет данные без обращения к модели; «Учесть ответы и уточнить разбор» сначала сохраняет, затем отправляет материалы в API. При ошибке API ответы и предыдущие материалы остаются сохранёнными.

AI получает исходные формулировки вопросов, ответы, текст TXT/MD и приложенные изображения. Аудио/видео не транскрибируются: учитываются метаданные и пояснения пользователя. Ответы сохраняются после перезапуска, входят в резервную копию и передаются следующим текстовым этапам. Старые ответы остаются редактируемыми, даже если вопрос исчез из уточнённого разбора. Утверждение устаревшего разбора после изменения ответов блокируется; требуется новый разбор. Предыдущий анализ и состояния этапов архивируются при повторном анализе.
